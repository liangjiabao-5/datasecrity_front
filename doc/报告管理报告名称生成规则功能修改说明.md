# 报告管理报告名称生成规则功能修改说明

更新时间：2026-06-10

## 修改范围

本次调整范围为“报告管理”页面中“生成数据安全风险评估报告”弹窗的“报告名称”默认生成规则。

涉及前端文件：
- `src/views/workflow/ReportManagementView.vue`
- `src/utils/reportName.ts`
- `scripts/reportName.test.mjs`

## 删除的功能

本次没有删除前端页面、按钮、提交字段或后端接口。

前端不再为了生成默认报告名称读取 `GET /api/v1/projects/{projectId}/survey/business-systems` 的 `systemName`。报告名称默认值不再由“公司名称-系统名称-数据安全风险评估报告”组成。

## 修改的功能

### 1. 报告名称默认组成规则

“报告名称”默认值调整为：

```text
公司名称-评估对象-数据安全风险评估报告
```

字段来源：
- 公司名称：优先取 `GET /api/v1/projects/{projectId}/basic-info` 返回的 `organization.name`。
- 公司名称回退：如果 `organization.name` 为空，则依次回退 `GET /api/v1/projects/{projectId}` 返回的 `assessmentOrg`、`projectName`。
- 评估对象：取 `GET /api/v1/projects/{projectId}/basic-info` 返回的 `assessmentTarget`。

兜底规则：
- 如果评估对象为空，前端默认生成 `公司名称-数据安全风险评估报告`。
- 如果公司名称和评估对象都为空，前端默认生成 `项目-数据安全风险评估报告`。

### 2. 生成报告弹窗打开流程

点击“生成报告”后，前端会在打开弹窗前加载以下数据：
- `GET /api/v1/projects/{projectId}/reports/readiness`
- `GET /api/v1/projects/{projectId}`
- `GET /api/v1/projects/{projectId}/basic-info`

前端读取以上数据后生成默认报告名称，并继续保留原有生成前检查、章节选择、报告类型选择和提交逻辑。

### 3. 报告生成提交参数

`POST /api/v1/projects/{projectId}/reports/generate` 的请求结构未变：

```json
{
  "reportName": "XX银行股份有限公司-OA办公系统-数据安全风险评估报告",
  "reportType": "DATA_SECURITY_RISK_ASSESSMENT",
  "selectedSections": [
    "BASIC_INFO",
    "PLAN",
    "SURVEY",
    "EVALUATION",
    "RISK_SUMMARY",
    "SUGGESTIONS"
  ]
}
```

其中示例里的 `OA办公系统` 表示项目基本信息中的 `assessmentTarget`，不是信息调研业务系统列表中的 `systemName`。

## 后端需要同步关注

1. 报告生成接口无需新增字段，但应继续以 `reportName` 作为报告记录名称、文件下载名称和审计追踪名称。
2. 如果后端存在未传 `reportName` 时自动生成名称的兜底逻辑，请同步改为“公司名称-评估对象-数据安全风险评估报告”。
3. 请确保 `basic-info` 接口稳定返回 `organization.name` 和 `assessmentTarget`。
4. 报告名称默认生成不再依赖 `survey/business-systems` 的 `systemName`，该接口不需要因为报告名称规则做调整。
5. 报告列表接口、任务状态接口、下载接口和删除接口字段不变，不需要因为本次调整新增返回字段。

## 接口变更结论

- 删除接口：无。
- 新增接口：无。
- 修改接口结构：无。
- 修改业务规则：报告名称默认生成规则变更，后端兜底命名逻辑和接口文档示例建议同步更新。
