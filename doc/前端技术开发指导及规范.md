# 前端技术开发指导及规范

## 1. 前端建设目标

前端负责把原型中的项目流程、标签页、表单、表格、弹窗、导入导出、分页和报告操作完整落地。页面实现应以业务流程为主线，而不是简单还原静态 HTML。所有保存、计算、生成和删除类操作都要与后端接口、权限和审计要求对齐。

## 2. 推荐技术栈

推荐：

- 框架：Vue 3
- 语言：TypeScript
- 构建：Vite
- UI 组件：Element Plus
- 状态管理：Pinia
- 路由：Vue Router
- 请求：Axios
- 表单校验：Element Plus Form Rules + 自定义校验工具
- 表格增强：Element Plus Table，复杂场景可封装业务表格组件
- 文件上传：Element Plus Upload + 后端文件接口

选择理由：当前原型是典型后台管理系统，Element Plus 能覆盖标签页、表单、表格、弹窗、分页、上传、下拉、多选、按钮组等主要交互。

## 3. 页面路由规划

| 路由 | 页面 | 原型文件 | 说明 |
| --- | --- | --- | --- |
| `/projects` | 项目管理 | `项目管理页面.html` | 项目列表、状态筛选、详情弹窗、模板保存 |
| `/projects/create` | 创建项目 | `创建项目页面.html` | 新建项目表单 |
| `/projects/:projectId/edit` | 编辑项目 | `编辑项目页面.html` | 修改项目配置 |

| `/projects/:projectId/plan` | 评估方案 | `评估方案-评估团队.html` | 团队、被评估方、关注点、差距项 |
| `/projects/:projectId/survey` | 信息调研 | `信息调研.html` | 系统、资产、处理活动、防护措施 |
| `/projects/:projectId/evaluation` | 现场测评 | `现场测评.html` | 检查项、评估结果、分数计算、案例建议 |

## 4. 页面布局规范

### 4.1 主布局

- 左侧导航固定展示：项目管理、评估方案、信息调研、现场测评、汇总分析、报告管理、知识库管理、系统设置。
- 顶部区域展示当前项目名称、用户信息和面包屑。
- 项目内页面必须带 `projectId`，页面加载时先获取项目摘要，用于标题和权限判断。
- 非项目页面，如知识库管理，不依赖 `projectId`。

### 4.2 页面内容区

- 列表页采用“筛选/状态区 + 操作栏 + 表格 + 分页”结构。
- 表单页采用“标签页 + 操作栏 + 表单区”结构。
- 弹窗用于新增、编辑、确认、详情查看，不在弹窗里承载过深流程。
- 所有主按钮位置保持一致：查询/重置在筛选区，新增/导入/导出/保存/下一步在操作栏。

## 5. 通用组件设计

| 组件 | 用途 | 关键能力 |
| --- | --- | --- |
| `AppLayout` | 系统主布局 | 左侧导航、顶部栏、内容区 |
| `ProjectHeader` | 项目内页面头部 | 项目名称、当前步骤、快捷跳转 |
| `StatusTabs` | 项目状态或评估结果筛选 | 显示数量、切换状态、触发查询 |
| `PageToolbar` | 页面按钮栏 | 按权限控制按钮显示 |
| `DataTable` | 通用表格 | 分页、勾选、操作列、空状态、加载状态 |
| `EditDialog` | 新增/编辑弹窗 | 表单校验、确认、取消 |
| `ImportDialog` | 导入弹窗 | 上传文件、导入进度、错误明细下载 |
| `FileUploader` | 文件上传 | 类型限制、大小限制、上传进度 |
| `DictionarySelect` | 字典/知识库下拉 | 单选、多选、远程搜索 |
| `ConfirmButton` | 危险操作按钮 | 二次确认、防重复提交 |
| `ReportTaskStatus` | 报告任务状态 | 轮询、失败提示、下载入口 |

## 6. 状态管理规范

使用 Pinia 建议拆分以下 store：

- `useAuthStore`：登录用户、权限、角色。
- `useProjectStore`：当前项目摘要、项目配置、项目状态。
- `useDictStore`：风险类型、评估结果、风险等级、系统类型等字典。
- `useKnowledgeStore`：模板、模型、矩阵等可复用配置的缓存。
- `useTaskStore`：导入、导出、报告生成等异步任务状态。

状态原则：

- 页面表单数据优先放在页面组件内，提交成功后再刷新 store。
- 跨页面共享的当前项目、用户权限、字典数据放 store。
- 不在前端长期保存敏感文件地址，下载时通过后端接口换取。

## 7. 接口调用规范

### 7.1 请求封装

- 统一使用 `request.ts` 封装 Axios。
- 请求头带 `Authorization`。
- 响应统一处理 `code`、`message`、`data`。
- `401` 跳转登录，`403` 展示无权限，`500` 展示错误摘要。
- 防重复提交：保存、删除、生成、计算等操作按钮在请求中置为 loading。

### 7.2 分页参数

前端统一传：

```ts
{
  pageNo: 1,
  pageSize: 10,
  keyword?: string,
  filters?: Record<string, unknown>
}
```

后端统一返回：

```ts
{
  list: T[],
  pageNo: number,
  pageSize: number,
  total: number
}
```

## 8. 页面开发要求

### 8.1 项目管理

标签页/视图：

- 全部、待开始、进行中、已完成按项目状态筛选。
- 切换状态后清空当前页码，重新查询第一页。

按钮：

- 创建新项目：跳转 `/projects/create` 或打开创建弹窗。
- 查看：打开项目详情弹窗。
- 开始评估：调用开始评估接口，成功后进入 `/projects/:id/basic`。
- 编辑：进入 `/projects/:id/edit`。
- 删除：二次确认后调用删除接口。
- 添加成员：在详情弹窗中新增团队成员。
- 存入模板：保存项目配置为模板。

前端注意：

- 列表状态数量由后端返回，不在前端用当前页计算。
- 删除、开始评估、存入模板必须按权限控制。
- 详情弹窗中的团队成员修改后，项目列表无需全量刷新，只刷新详情即可。

### 8.2 创建/编辑项目

字段：

- 项目名称、项目编号、评估单位必填。
- 风险评价矩阵、评估模板、系统类型、风险危害程度分析模型、评分模型必选。
- 项目描述可选。

按钮：

- 取消：返回来源页。
- 创建项目/保存修改：校验表单后提交。

前端注意：

- 项目编号唯一性由后端校验，前端可做失焦预校验。
- 编辑已有项目时，如果修改评估模板、评分模型、风险危害程度模型、风险评价矩阵，应展示影响提示。

### 8.3 项目基本信息

标签页：

- 项目基本情况：项目描述、系统描述、法规、标准、评估计划。
- 被评估单位基本信息：单位信息、负责人、公司简介、联系人。

按钮：

- 导入：打开导入弹窗。
- 导出：下载当前项目基本信息。
- 保存：保存当前标签页。
- 下一步：保存后进入评估方案。
- 添加自定义：在法规或标准选择器中新增项目自定义项。

前端注意：

- 法规和标准是多选字段，展示时按用户选择顺序输出。
- 联系方式字段做格式校验，但不能过度限制固话、邮箱等合法格式。

### 8.4 评估方案

标签页：

- 评估团队：评估机构人员。
- 被评估方团队：被评估单位配合人员。
- 关注点：风险关注点。
- 差距项：历史对比和改进项。

按钮：

- 查询/重置：列表查询。
- 增加：按当前标签页打开新增弹窗。
- 导入/导出：当前标签页数据导入导出。
- 修改/删除：列表操作列。
- 选择已有案例：从案例库选择关注点。
- 保存/下一步：保存方案并流转。

前端注意：

- 四个标签页的数据结构不同，不建议强行复用同一个表单配置。
- 删除人员时提示是否影响报告输出。

### 8.5 信息调研

标签页：

- 业务和信息系统调研。
- 数据资产调研。
- 数据处理活动调研。
- 安全防护措施调研。

按钮：

- 导入/导出/保存/下一步。
- 上传拓扑图、上传业务流程图。
- 增加行、删除。
- 应用建议。

前端注意：

- 数据资产表格字段多，建议支持横向滚动和行内编辑。
- 七类处理活动使用同一组件，通过活动类型切换字段展示。
- 上传文件前校验类型和大小。
- 导入失败要展示错误明细，支持下载错误报告。

### 8.6 现场测评

标签页/视图：

- 左侧检查项目录：数据安全管理、数据处理活动及子分类。
- 评估结果筛选：全部、不符合、符合、基本符合。
- 参考案例对比分析：作为评估记录编辑的辅助区域。

按钮：

- 导出模板：下载现场测评录入模板。
- 查询/重置：按检查项分类和评估结果筛选。
- 导入/导出：批量导入或导出测评记录。
- 分数计算：打开计算结果弹窗。
- 下一步：进入汇总分析。
- 全选/确定：批量修改评估结果。
- 编辑：打开检查记录表单。
- 保存/取消/关闭。
- 应用建议：把案例建议写入整改建议。

前端注意：

- 风险类型是多选。
- 批量修改要显示影响条数。
- 分数计算成功后刷新当前项目评分摘要。
- 编辑弹窗保存后只刷新当前行，避免大表格闪烁。

### 8.7 汇总分析

标签页：

- 数据安全风险源清单。
- 数据安全风险清单。
- 数据安全风险处置建议。

按钮：

- 刷新统计数据：重新汇总生成草稿。
- 修改：按当前标签页打开修改弹窗。
- 确定/取消/关闭。
- 下一步：进入报告管理。

前端注意：

- 刷新统计数据前提示是否覆盖未确认内容。
- 风险清单中的风险等级可以展示自动计算标识和人工修改标识。
- 风险源和风险清单要提供追溯入口，能查看来源检查项。

### 8.8 报告管理

按钮：

- 生成：打开报告生成配置，选择报告内容和报告名称。
- 刷新：刷新报告任务状态。
- 下载：下载已生成报告。
- 删除：删除报告记录。
- 分页按钮：切换列表。

前端注意：

- 报告生成采用异步任务，生成中轮询状态。
- 生成失败展示失败摘要。
- 下载按钮只在生成完毕时可用。

### 8.9 知识库管理

标签页：

- 评估项模板设置。
- 风险处置建议管理。
- 评分模型管理。
- 风险危害程度分析模型管理。
- 风险评价矩阵管理。
- 系统模板、数据处理活动、安全防护措施。

按钮：

- 添加模板、添加活动、添加措施、添加建议、添加模型、添加规则、新增矩阵、添加案例。
- 编辑、删除、导出、查看。
- 保存、保存配置、取消、关闭。

前端注意：

- 被项目引用的知识库条目删除时，前端展示“停用”而不是直接删除。
- 评分模型区间配置必须在前端先做覆盖和重叠校验，后端再做最终校验。
- 风险评价矩阵建议用可编辑矩阵组件实现。

## 9. 权限控制

前端权限控制分三层：

- 路由权限：无权限路由不可进入。
- 页面按钮权限：新增、编辑、删除、导入、导出、生成、计算等按钮按权限显示。
- 数据权限：项目列表和详情以后端返回为准，前端不自行扩大范围。

前端权限控制只用于体验优化，后端必须做最终权限校验。

## 10. 表单与校验规范

- 必填字段在 label 显示 `*`。
- 保存前做必填、格式、长度、枚举值校验。
- 下拉选项来自后端字典或知识库接口，不写死在页面里。
- 日期范围开始时间不得晚于结束时间。
- 评分模型区间必须覆盖 0%-100%，无重叠、无空档。
- 删除、批量修改、重新计算、报告生成、报告删除必须二次确认。

## 11. 文件上传下载规范

- 拓扑图、业务流程图支持图片格式，建议限制为 PNG/JPG/JPEG。
- 导入文件建议支持 XLSX。
- 报告下载由后端返回文件流或短时下载地址。
- 上传成功后前端保存文件 ID，不直接保存本地路径。

## 12. 代码规范

- 组件名使用 PascalCase。
- API 文件按领域拆分：`projectApi.ts`、`surveyApi.ts`、`evaluationApi.ts`、`riskApi.ts`、`reportApi.ts`、`knowledgeApi.ts`。
- 页面组件只处理交互和展示，复杂业务逻辑放 composable 或 store。
- 类型定义集中在 `types/` 下，接口响应不要使用 `any`。
- 保存类请求必须处理 loading、成功提示、失败提示和重复提交。

## 13. 联调要求

- 每个页面先联调列表和详情，再联调新增编辑，最后联调导入导出和复杂操作。
- 前端根据接口文档维护 mock 数据，字段名以接口文档为准。
- 报告生成、导入、导出、分数计算属于重点联调用例，需要覆盖成功和失败场景。
