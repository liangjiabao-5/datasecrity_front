## 背景与目标

排查接口返回成功、业务失败、HTTP 错误及网络错误时，前端是否通过消息、弹窗或页面错误状态告知用户，并定位返回文案被丢弃、错误被吞掉及错误的成功提示。

本次基于当前工作区，包括已有未提交改动；未修改业务源码、构建产物或后端数据。归档范围涉及多个模块，按项目约定放入跨模块联动目录。

## 实际执行内容

- 检索 `src/api/` 的 12 个文件、127 个 API 对象方法，追踪页面、组件、路由、store、请求工具中的调用和异常传播。127 是方法数量，包含本地辅助方法、Mock 方法和当前没有调用的方法，不等于 127 个实际接口。
- 检索 22 个 Vue 文件中的接口调用、`ElMessage`、弹窗、页面错误状态、空 catch、`finally`、`Promise.allSettled` 和直接下载入口。
- 核对统一响应结构、现有接口文档及成功响应中的 `message`、`warnings` 等反馈字段。
- 用真实 TypeScript 源码转译后运行隔离检查：请求层使用真实 Axios 和替换后的 adapter；页面检查提取当前源码中的原函数。共执行 24 项检查，无真实网络请求、无真实新增/保存/删除操作。

### 判定口径

1. **完全没有错误反馈**：接口失败后，页面无消息、弹窗或错误状态。Console 异常不算用户提示。
2. **成功有反馈，但后端文案丢失**：页面已提示“保存成功”等固定文字，不归为完全无反馈；后端成功 `message` 的附加信息仍可能丢失。
3. **没有操作提示，但有可见变化**：如删除后表格行消失、浏览器开始下载，单独列出，避免误报成完全没有反馈。
4. 正常列表查询、详情展示、后台 Token 刷新成功不要求逐次弹出“成功”；成功数据已展示即有反馈。
5. 以下路径省略环境前缀 `/api/v1`；`{p}` 表示项目 ID，`{id}` 表示对应记录 ID。

## 检查结论

### 一、统一请求层存在跨模块缺口

源码：`src/utils/request.ts:39`、`:67`、`:115`、`:123`、`:136`、`:172`、`:188`。

| 响应场景 | 当前请求层行为 | 用户提示结论 |
| --- | --- | --- |
| HTTP 200，`code !== SUCCESS` | `parseApiPayload` 在 `http.*().then(unwrap)` 中抛出 `ApiError`；不进入 Axios 的 HTTP 错误提示分支 | 页面无 catch 时完全无错误提示，即使业务 code 表示无权限或校验失败 |
| HTTP 400/404/409/422/429 等 | 整理错误后 reject | 页面无 catch 时完全无错误提示 |
| 断网、超时及其他无 HTTP 状态的失败 | 整理错误后 reject | 页面无 catch 时完全无错误提示 |
| HTTP 403 | 固定提示“无权限执行当前操作” | 有提示，但统一层未展示后端具体 `message`；页面自行 catch 时才可能补充原因 |
| HTTP >= 500 | 提示“服务异常：{message}” | 普通 JSON 错误有统一提示；页面再次提示时可能重复 |
| 业务请求 HTTP 401，刷新失败 | 清理会话并跳转登录，通常提示登录失效 | 属于已有反馈；登录页或正在跳转时会抑制重复提示 |
| `SUCCESS` 普通 JSON | `get/post/put/delete` 只返回 `data` | 顶层 `message` 被丢弃，页面无法读取后端成功文案 |
| `postEnvelope` | 保留完整响应体 | 当前仅风险“更新合并”使用，并展示返回 `message` |

`src/main.ts:21` 未注册将这些异常转换为用户提示的全局 `app.config.errorHandler`，也未发现 `unhandledrejection` 提示兜底。部分页面注释称“请求层统一展示错误”，但实际只覆盖上述部分状态。
