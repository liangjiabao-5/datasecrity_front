# 国标指标处理活动默认关联前端对接说明

更新时间：2026-08-13  
适用页面：汇总分析 → 数据安全风险源清单

## 1. 修改目标

风险源清单生成后，前端应直接展示后端已计算的两列默认值：

| 页面列 | 接口字段 | 默认生成规则 |
| --- | --- | --- |
| 涉及的数据处理活动 | `relatedActivities` | 当前国标指标配置的处理活动，与“信息调研 → 数据处理活动调研 → 涉及处理活动类型”的交集。 |
| 涉及的数据及类型、级别 | `relatedData` | 使用 `relatedActivities` 筛选数据资产后，按既有规则汇总的字符串。 |

前端不需要维护“指标—处理活动”映射，也不需要自行计算交集或默认数据类别、级别。

## 2. 刷新汇总分析

继续调用既有接口：

```http
POST /api/v1/projects/{projectId}/risk-summary/refresh
Content-Type: application/json

{
  "overwriteManualChanges": false
}
```

### 2.1 调用时机

1. 用户在现场测评保存“基本符合”或“不符合”记录后，点击“刷新汇总分析”。
2. 用户在信息调研页面保存“涉及处理活动类型”后，如需更新已生成风险源的默认值，应引导用户重新点击“刷新汇总分析”。
3. 用户补充、修改数据资产的“数据处理活动、数据类别、数据级别”后，如需更新已生成风险源的 `relatedData`，同样需重新刷新。

### 2.2 是否覆盖人工修改

- `overwriteManualChanges: false`：保留已经在风险源清单中人工编辑过的行；这类行不会重新计算 `relatedActivities` 和 `relatedData`。
- `overwriteManualChanges: true`：使用最新指标映射、信息调研活动和数据资产覆盖自动生成字段，同时会重置该行后续风险评审结果。

若刷新响应中的 `retainedManualRecords` 大于 `0`，前端应提示：

> 存在已人工调整的风险源未重新计算；如需按最新信息调研数据更新，请选择“覆盖人工修改”后再次刷新。

## 3. 风险源清单列表展示

继续调用既有接口：

```http
GET /api/v1/projects/{projectId}/risk-sources?pageNo=1&pageSize=10
```

响应行中的相关字段示例：

```json
{
  "id": "risk-record-id",
  "assessmentItemId": "AQGL001",
  "relatedActivities": ["收集", "传输"],
  "relatedData": "综合管理-数字化管理（一般数据Ⅲ级）、业务数据-交易管理（一般数据Ⅱ级）"
}
```

展示要求：

1. `relatedActivities` 是数组。表格内可用 `、` 拼接显示；编辑态保留数组，绑定多选组件。
2. `relatedData` 是已经聚合好的字符串，表格内直接展示，不要再次按分隔符重算分类或级别。
3. `relatedActivities` 为空数组时，显示 `-` 或空占位；`relatedData` 为 `-` 时显示 `-`。
4. 正式“数据安全风险清单”和“风险处置建议”页沿用现有只读展示逻辑，不要在这两个页面提供这两个字段的编辑入口。

## 4. 风险源编辑弹窗

风险源清单允许人工调整这两项，保存接口不变：

```http
PUT /api/v1/projects/{projectId}/risk-sources/{riskSourceId}
Content-Type: application/json
```

提交示例：

```json
{
  "relatedActivities": ["收集", "传输"],
  "relatedData": [
    "综合管理-数字化管理（一般数据Ⅲ级）",
    "业务数据-交易管理（一般数据Ⅱ级）"
  ]
}
```

后端会将 `relatedData` 数组用 `、` 拼接后存储，并在接口响应中返回字符串。

### 4.1 编辑顺序与联动

1. 先加载并回显 `relatedActivities`。
2. 使用当前 `relatedActivities` 请求候选项：

```http
GET /api/v1/projects/{projectId}/risk-form-options?relatedActivities=收集、传输
```

3. 将响应的 `relatedDataOptions` 绑定到“涉及的数据及类型、级别”多选组件。
4. 用户变更 `relatedActivities` 时，立即清空本次尚未保存的 `relatedData` 选择，再按新活动重新请求候选项。
5. `relatedActivities` 为空时，不请求或忽略候选项；禁用“涉及的数据及类型、级别”多选。

接口响应：

```json
{
  "relatedActivityOptions": ["收集", "传输", "存储", "使用和加工", "提供", "公开", "删除"],
  "relatedDataOptions": [
    "综合管理-数字化管理（一般数据Ⅲ级、一般数据Ⅱ级）"
  ]
}
```

### 4.2 空候选项提示

当 `relatedActivities` 非空而 `relatedDataOptions` 为空时，提示：

> 所选处理活动未匹配到数据资产，请在“信息调研 → 数据资产调研”维护数据处理活动、数据类别和数据级别。

此时允许保存处理活动；涉及的数据及类型、级别可保持为空，后端会保存为 `null`，列表刷新后按实际数据展示。

## 5. 前端无需处理的内容

- 不需要读取、上传或解析 `涉及的数据处理活动.xlsx`。
- 不需要从 `assessmentItemId` 推导处理活动；映射已在后端模板中维护。
- 不需要把信息调研中的活动编码（如 `COLLECT`）直接传入风险源默认数据计算；后端已完成编码与中文活动的转换及交集计算。

## 6. 验收场景

1. 信息调研勾选“收集、传输”，指标配置为“收集、存储、传输、使用和加工、提供、公开、删除”时，风险源默认显示“收集、传输”。
2. 数据资产中有“收集”和“传输”对应资产时，风险源默认 `relatedData` 显示对应数据类别前两级与汇总级别。
3. 未勾选信息调研活动、交集为空或未命中有效数据资产时，`relatedActivities` 为空、`relatedData` 显示 `-`。
4. 人工修改风险源并在刷新时不覆盖时，修改值保留；选择覆盖后，恢复为后端按最新调研数据计算的默认值。
