# 风险源清单“涉及的数据及类型、级别”下拉选项调整说明

更新时间：2026-07-29

## 1. 调整范围

本次仅调整“汇总分析 - 数据安全风险源清单”编辑弹窗中 `relatedData`（涉及的数据及类型、级别）下拉选项的生成规则。

原规则是按项目下全部数据资产的 `dataCategory/dataLevel` 直接拼接；新规则需要依据当前风险源行已选择的 `relatedActivities`（涉及的数据处理活动）筛选数据资产，再按数据类别前两级汇总数据级别。

风险源清单保存接口、`relatedData` 的存储字段和多选保存方式保持不变。

## 2. 接口调整

接口地址保持不变，扩展查询参数：

```http
GET /api/v1/projects/{projectId}/risk-form-options?relatedActivities=收集、传输、存储
```

| 参数 | 必填 | 类型 | 说明 |
| --- | --- | --- | --- |
| `projectId` | 是 | path | 项目 ID。 |
| `relatedActivities` | 否 | query string | 当前风险源行已选择的处理活动，使用顿号 `、` 拼接。未传或为空时，`relatedDataOptions` 返回空数组。 |

后端应兼容活动中文名称和处理活动编码两种入参。编码映射如下：

| 编码 | 中文名称 |
| --- | --- |
| `COLLECT` | 收集 |
| `TRANSFER` | 传输 |
| `STORE` | 存储 |
| `USE_PROCESS` | 使用和加工 |
| `PROVIDE` | 提供 |
| `PUBLIC` | 公开 |
| `DELETE` | 删除 |

响应结构不新增字段：

```json
{
  "code": "SUCCESS",
  "message": "Operation succeeded.",
  "data": {
    "relatedDataOptions": [
      "综合管理-数字化管理（一般数据Ⅲ级、一般数据Ⅱ级）"
    ],
    "relatedActivityOptions": [
      "收集",
      "传输",
      "存储",
      "使用和加工",
      "提供",
      "公开",
      "删除"
    ]
  }
}
```

## 3. 后端数据来源

后端按项目查询“信息调研 - 数据资产调研 - 数据资产情况”中的有效数据资产记录（`data_asset.deleted = false`），至少需要读取以下字段：

| 数据资产字段 | 接口字段 | 用途 |
| --- | --- | --- |
| 数据处理活动 | `flow_description` / `flowDescription` | 判断该资产是否匹配当前处理活动。 |
| 数据类别 | `data_category` / `dataCategory` | 提取前两级分类，作为下拉选项的分组名称。 |
| 数据级别 | `data_level` / `dataLevel` | 汇总到同一分类分组的括号中。 |

数据类别、数据级别或数据处理活动为空的资产不能生成下拉选项，应跳过。

## 4. 聚合规则

1. 将请求中的 `relatedActivities` 统一为中文活动名称，并去重。
2. 遍历当前项目全部有效数据资产。若数据资产 `flowDescription` 包含任一已选择活动名称，则该数据资产命中；同一资产命中多个活动时只计入一次。
3. 对命中资产读取 `dataCategory` 与 `dataLevel`：
   - `dataCategory` 按连字符 `-` 分层，去除每层首尾空白；
   - 取前两层并以 `-` 拼接为分类分组键；只有一层时使用该层；
   - 同一分组内的数据级别去重，并按数据资产创建时间升序保留首次出现顺序。
4. 每个分类分组生成一条 `relatedDataOptions`：

```text
前两级数据类别（数据级别1、数据级别2）
```

5. 分组的输出顺序按该分组首次命中的数据资产创建时间升序；不要再混入与当前活动无关的数据资产，也不要返回旧的“数据类别/数据级别”格式。

### 示例

当前风险源行已选择“收集、传输”。以下两条数据资产的“数据处理活动”均包含其中至少一种活动：

| 数据类别 | 数据级别 |
| --- | --- |
| 综合管理-数字化管理-信息运营管理 | 一般数据Ⅲ级 |
| 综合管理-数字化管理-信息运营管理 | 一般数据Ⅱ级 |

两条记录的前两级分类均为“综合管理-数字化管理”，因此下拉框仅返回一项：

```text
综合管理-数字化管理（一般数据Ⅲ级、一般数据Ⅱ级）
```

## 5. 前端交互约定

1. 编辑风险源时，前端先展示并选择“涉及的数据处理活动”。
2. 每次活动选择变化后，前端清空本次未保存的 `relatedData` 选择，并携带最新 `relatedActivities` 调用 `risk-form-options`。
3. `relatedDataOptions` 为空时，前端提示“所选处理活动未匹配到数据资产”，并引导评估人员维护数据资产的“数据处理活动、数据类别、数据级别”。
4. 保存仍调用既有接口：

```http
PUT /api/v1/projects/{projectId}/risk-sources/{riskSourceId}
```

```json
{
  "relatedActivities": ["收集", "传输"],
  "relatedData": ["综合管理-数字化管理（一般数据Ⅲ级、一般数据Ⅱ级）"]
}
```

后端仍可将 `relatedData` 数组用顿号 `、` 拼接后存入既有 `related_data` 字段，列表和风险清单的回显格式保持字符串即可。

## 6. 验收点

1. 只选择“收集”时，仅返回数据处理活动列包含“收集”的数据资产聚合结果。
2. 选择多个处理活动时，返回各活动命中资产的并集；同一资产和同一数据级别均不重复计入。
3. 同一前两级数据类别下存在多个级别时，级别以顿号拼接并放入中文括号。
4. 数据类别只有一层时，仍可生成“该分类（数据级别）”。
5. 数据资产的 `flowDescription`、`dataCategory` 或 `dataLevel` 为空时，不生成无效或空白下拉项。
6. 修改处理活动后，旧的未保存数据选择不会继续作为新活动范围内的可选项。
