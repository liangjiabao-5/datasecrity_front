# 信息调研数据资产、数据处理活动字段调整说明

更新时间：2026-07-29

## 调整范围

本次调整只扩展信息调研的展示与字段，不改变既有接口地址、保存方式和处理活动枚举。

已同步的后端接口：

```http
GET /api/v1/projects/{projectId}/survey/processing-activity-survey
PUT /api/v1/projects/{projectId}/survey/processing-activity-survey
```

所有新增字段均为字符串。未填写时，接口返回空字符串 `""`。

## 1. 数据资产调研

数据资产调研表的列标题和编辑表单标签由“数据流转情况”调整为“数据处理活动”。

- 前端显示文案：`数据处理活动`
- 保持原有接口字段：`flowDescription`
- 不新增、不删除、也不改名 `data-assets` 接口字段；已有数据继续按 `flowDescription` 读写。
- 列表、详情/新增编辑弹窗、导入导出提示中的同名文案均应同步替换。

示例：

```json
{
  "flowDescription": "客户管理系统采集后，传输至数据仓库并用于客户服务"
}
```

## 2. 数据处理活动调研

在“数据处理活动调研”页面中，每个处理阶段增加“数据范围”输入项；数据传输阶段额外增加“数据链路盘点”。原字段保留，新增字段需要同时纳入页面初始化、编辑回显和保存 payload。

| 页面阶段 | 页面字段 | 请求/响应字段 | 说明 |
| --- | --- | --- | --- |
| 数据收集 | 数据范围 | `collectionDataScope` | 既有字段，位置调整为本阶段第一项，不需要新建字段。 |
| 数据存储 | 数据范围 | `storageDataScope` | 新增。 |
| 数据传输 | 数据范围 | `transferDataScope` | 新增。 |
| 数据传输 | 数据链路盘点 | `transferDataLinkInventory` | 新增；填写链路清单，并应与业务流程图保持一致。 |
| 数据使用和加工 | 数据范围 | `useDataScope` | 新增。 |
| 数据提供 | 数据范围 | `provideDataScope` | 新增；不要与既有的 `provideScope`（数据提供范围）混用。 |
| 数据公开 | 数据范围 | `publicDataScope` | 新增；不要与既有的 `publicScope`（对象范围）混用。 |
| 数据删除 | 数据范围 | `deletionDataScope` | 新增。 |
| 数据出境 | 数据范围 | `crossBorderDataScope` | 新增；与 `crossBorderPresence` 同时维护。 |

处理活动勾选与阶段表单的既有联动规则保持不变：`involvedActivities` 中选中某一阶段时展示/启用对应字段；数据出境区域仍按原页面规则展示。

### 保存示例

前端在原有 `PUT` 请求中增加以下字段即可：

```json
{
  "involvedActivities": ["COLLECT", "TRANSFER", "STORE", "USE_PROCESS", "PROVIDE", "PUBLIC", "DELETE"],
  "collectionDataScope": "客户基础信息、订单信息",
  "storageDataScope": "客户基础信息、订单信息",
  "transferDataScope": "客户基础信息、订单信息",
  "transferDataLinkInventory": "客户管理系统→数据交换平台→数据仓库",
  "useDataScope": "客户基础信息、订单信息",
  "provideDataScope": "客户基础信息",
  "publicDataScope": "脱敏后的统计数据",
  "deletionDataScope": "超过保存期限的客户信息",
  "crossBorderDataScope": "境外云服务日志数据",
  "crossBorderPresence": "NO"
}
```

## 3. 前端改造清单

1. 修改数据资产调研的列标题、表单标签和帮助提示；接口绑定仍使用 `flowDescription`。
2. 在数据处理活动表单状态、默认值、接口响应回填和提交 payload 中加入上述 8 个新增字段。
3. 在阶段内将“数据范围”放在其他具体字段之前；传输阶段的顺序为：数据范围、数据链路盘点、在线通道、离线传输、传输协议、数据接口。
4. `provideDataScope` 与 `provideScope`、`publicDataScope` 与 `publicScope` 必须分别保留独立输入框和独立绑定字段。
5. 页面通过 Word 导入成功或重新打开页面后，重新调用 `GET /processing-activity-survey`，确保新增字段回显；Word 导出不需要前端额外组装。

## 4. 联调验收

1. 填写新增字段后保存并刷新页面，所有字段值应完整回显。
2. 仅填写某一阶段的“数据范围”时，该阶段应按现有规则被识别为已涉及的处理活动。
3. 数据传输阶段同时保存 `transferDataScope` 和 `transferDataLinkInventory`，两项互不覆盖。
4. 数据提供、数据公开页面中，“数据范围”与原“数据提供范围/对象范围”应分别保存。
5. 下载并导入最新调研模板后，表 A.7 的新增内容应回填到同名页面字段；导出 Word 时也应带回填写值。
