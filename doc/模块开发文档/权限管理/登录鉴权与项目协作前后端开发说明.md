# 登录鉴权与项目协作前后端开发说明

## 1. 文档目标与适用范围

> **实现状态（2026-08-04）：** 本文档中的后端鉴权、RBAC、项目协作、迁移脚本和初始化命令已完成实现；前端登录页、系统设置页和协作人界面仍需按本文约定对接。以下“目标状态”表述保留为设计背景，接口实现以本文第 8 节及《后端接口文档》为准。

本文档定义“用户名密码登录、用户/角色/权限管理、项目所有者与项目协作人”迭代的前后端分工、接口契约、数据模型和联调规则，供后端、前端及测试人员共同执行。

已确认的业务规则如下：

- 首期账号由本系统维护，使用“用户名 + 密码”登录；后续预留钉钉扫码登录接入能力。
- `SUPER_ADMIN`（超级管理员）拥有用户、角色、权限、全部项目和知识库的完整管理权限。
- 普通用户创建项目后自动成为项目所有者；只能查看、编辑自己创建的项目及被授权协作的项目。
- 项目所有者可以为自己的项目添加或移除协作人。
- 项目协作人均具有被授权项目的查看和编辑权限；首期不提供只读协作人。
- 历史项目统一回填至初始超级管理员账号，后续可由超级管理员转交给实际负责人。

本文档描述的是**本次迭代目标状态**。当前后端仅有临时 Bearer Token 占位逻辑，当前前端无登录页、用户管理页和项目协作人管理页；在接口和页面开发完成前，不应将本文中新增接口视为已上线能力。

## 3. 权限模型与判定规则

### 3.1 RBAC 与项目授权结合

系统使用两层判断：

1. **RBAC（角色权限）**：判断用户是否可以使用某类功能，例如创建项目、管理用户或管理知识库。
2. **项目关系授权**：判断用户是否能访问某一个具体项目。项目所有者和有效协作人拥有项目关系；超级管理员不受项目关系限制。

仅有“项目编辑”权限并不代表能够编辑任意项目，仍须同时满足“项目所有者、有效协作人或超级管理员”之一。后端必须执行两层校验，前端隐藏按钮仅用于改善体验，不能替代后端控制。

### 3.2 初始角色与权限代码

| 角色代码 | 角色名称 | 首期权限范围 |

| `USER` | 普通用户 | 创建项目；读取项目创建所需的知识库下拉数据；在其项目关系范围内读取和编辑项目；删除自己拥有的项目；管理自己拥有项目的协作人。 |

### 3.3 项目访问判定

后端对包含 `projectId` 的请求按以下顺序判定：

1. Access Token 不存在、无效、过期或账号已停用：返回 `401`。
2. 当前用户具有 `SUPER_ADMIN`：允许访问全部项目。
3. 当前用户是 `project.owner_id`：允许查看、编辑、删除和协作人管理。
4. 当前用户在 `project_member` 中有 `ACTIVE` 状态的协作记录：允许查看和编辑。
5. 其余情况：返回 `403 PROJECT_ACCESS_DENIED`。

项目协作人不能删除项目、转交所有者或管理协作人。协作授权被撤销后，下一次接口请求立即失效；前端刷新或再次请求项目数据后应跳回项目列表。

## 4. 后端开发说明

### 4.1 鉴权中间件与配置

现有 `app/common/auth.py` 仅在 `AUTH_REQUIRED=true` 时检查请求头前缀，并将 Bearer Token 原样写入 `g.current_user_id`，不能用于正式鉴权。本次应替换为以下能力：

- 登录接口校验用户名和密码哈希，签发短期 Access Token；Refresh Token 仅通过 `HttpOnly` Cookie 保存。
- `before_request` 中间件解析 Access Token，加载用户状态、角色和权限，并写入 `g.current_principal`。
- 提供 `require_permission(...)`、`require_project_access(...)` 和 `visible_projects_query(...)` 等统一能力；蓝图或服务层不得自行拼接不一致的权限规则。
- 项目创建、保存、导入、报告任务等写入场景统一从当前主体回填 `created_by`、`updated_by` 和审计日志 `operator_id`，绝不接受前端提交的操作者 ID。
- 生产环境配置 JWT 密钥、Token 有效期和受信任前端来源；启用携带 Cookie 的跨域请求时，CORS 不能使用通配符来源。
- 在 `requirements.txt` 中新增 JWT 鉴权依赖和 Flask CORS 支持（建议采用 `Flask-JWT-Extended` 与 `Flask-Cors`，具体版本以实施时对 Flask 3 的兼容性验证为准）；不自行实现 JWT 签名、密码哈希或跨域响应头。
- 登录提供方抽象为 `LOCAL` 与后续可扩展的 `DINGTALK`。首期仅启用 `LOCAL`，钉钉接入时新增扫码发起、回调校验和 `sys_user_identity` 绑定逻辑，不改变项目授权模型。

建议新增的环境变量如下，真实密钥只放部署环境，不能提交到仓库：

```dotenv
AUTH_REQUIRED=true
JWT_SECRET_KEY=replace-with-a-random-production-secret
JWT_ACCESS_TOKEN_EXPIRES_MINUTES=30
JWT_REFRESH_TOKEN_EXPIRES_DAYS=7
AUTH_COOKIE_SECURE=true
AUTH_COOKIE_SAMESITE=Lax
CORS_ALLOWED_ORIGINS=https://frontend.example.com
```

开发环境可使用 `AUTH_COOKIE_SECURE=false`，但必须显式配置本地前端来源 `http://localhost:5173`。本次不要求 Redis；Refresh Token 的撤销状态存于 MySQL，继续沿用现有 MySQL 与 MinIO 文件存储。

密码策略由后端统一校验，首期建议为 8-64 个字符、至少包含字母和数字、不得包含空白字符。登录页、用户新建页、管理员重置密码页和修改密码页应使用相同规则做前置提示，但以后端校验结果为准。

### 4.2 数据库迁移要求

详细字段、索引和约束见 [数据库概要设计](../../数据库概要设计.md) 的“登录与权限管理域”。实施时使用 Alembic 正式迁移，不将用户、角色或项目授权表加入 `apply_runtime_schema_updates` 的临时补丁。

迁移顺序：

1. 创建身份、角色、权限、关系、Refresh Token 和外部身份绑定表；创建初始权限字典和内置角色。
2. 使用交互式 CLI 创建初始超级管理员，禁止在迁移脚本或种子数据中写入默认明文密码。
3. 为 `project` 增加可空的 `owner_id` 和索引。
4. 将历史有效项目的 `owner_id` 统一回填为初始超级管理员 ID。
5. 校验不存在空所有者后，将 `owner_id` 改为非空并添加外键。
6. 将项目创建、更新、导入、报告和审计操作接入当前主体信息。
7. 在测试环境启用 `AUTH_REQUIRED=true` 后，完成回归测试再切换生产环境。

### 5.3 前端身份状态与请求规则

1. 登录成功后将 `accessToken` 仅保存在内存状态；Refresh Token 由后端写入 `HttpOnly` Cookie，前端不得读取或写入 Refresh Token。
2. 请求拦截器为业务请求增加 `Authorization: Bearer {accessToken}`；需要携带 Cookie 的请求启用 `withCredentials=true`。
3. 响应为 `401` 时，前端仅调用一次 `/auth/refresh` 后重放原请求；刷新失败则清空本地身份状态并跳转 `/login?redirect={当前路径}`。
4. 响应为 `403` 时不循环刷新 Token，提示后端返回的无权限信息；若发生在项目详情页，则返回项目列表。
5. 首次进入已登录页面先调用 `/auth/me` 恢复主体信息；路由守卫在主体信息未加载完成前不渲染受保护页面。
6. 普通用户不显示“系统设置”和“知识库管理”菜单；项目创建表单所需的模板、评分模型和矩阵下拉项仍可通过只读接口取得。

### 5.4 项目协作人交互流程

**添加协作人：** 项目所有者或超级管理员打开“项目协作人”面板 → 查询已有用户（排除项目所有者、已在成员列表和停用账号）→ 选择用户并确认 → 调用新增成员接口 → 刷新成员列表和项目详情权限字段。

**移除协作人：** 打开成员列表 → 选择协作人 → 二次确认 → 调用移除接口 → 刷新列表。被移除用户在下一次项目请求时收到 `403`，其前端页面应跳回项目管理页。

**转交所有者：** 仅超级管理员在项目操作菜单中可见 → 选择有效用户 → 二次确认并展示影响说明 → 调用转交接口。原所有者默认不自动成为协作人；如需保留其编辑权，应由管理员在转交后显式添加为协作人。

## 6. 前后端接口与联调规则

完整请求、响应、错误码见 [后端接口文档](../../后端接口文档.md) 第 13 节。前端需按以下约定实现：

- 所有新增接口均使用 `/api/v1` 前缀及现有统一响应包装：`{ code, message, data, traceId }`。
- `/auth/login`、`/auth/refresh` 为无需 Access Token 的公开接口；其余新增接口均要求登录。
- 用户、角色、权限接口仅超级管理员可调用；不要仅以菜单隐藏替代接口拦截。
- 新建项目请求中不提交 `ownerId`、`createdBy`、`tenantId`、角色或权限信息，所有者由后端根据当前登录用户设置。
- 新增协作人请求只提交 `userId`；后端负责校验账号状态、项目关系和操作人权限。
- 项目列表、详情和成员接口返回的 ID 均为字符串；日期采用 ISO 8601 字符串；前端不得用用户名代替用户 ID 提交。
- 前端收到密码、Token、Refresh Cookie 时不得打印到日志、通知内容或错误上报系统。
